Flagship Project · Fully Deployed

Taskr — Task Management Platform

React + Node.js + PostgreSQL + WebSockets + CI/CD

Live App Frontend API

The Challenge

Build a task management app that feels instant across multiple devices simultaneously, with secure per-user data isolation, cloud file storage, automated email flows, and zero manual deployment steps.

Key Technical Decisions

  • Used Socket.io personal rooms so updates push to only the correct user's devices — not broadcast to everyone
  • Optimistic UI updates for toggle and delete — UI responds instantly, rolls back if the server rejects
  • Prisma ORM with typed schema and versioned migrations — no raw SQL, no data loss risk on schema changes
  • DELETE with ownership in one query: WHERE id=$1 AND user_id=$2 — avoids a separate ownership check and prevents data leaks
  • Password reset tokens hashed before storage — if the database leaks, tokens are useless to an attacker

How I Think

Technical Approach

These aren't skills I list — they're principles I apply in every project.

Security is not optional

In Taskr I enforced ownership at the database query level (WHERE id=$1 AND user_id=$2), not just in middleware. I hashed password reset tokens before storage. I rate-limited auth routes to 5 requests per 15 minutes. These decisions came from understanding what breaks in production, not just what works in development.

Measure before you ship

I run Lighthouse audits before every deployment. I write integration tests against a real test database — not mocks. I check production headers with curl -I to verify security configuration. The 97 Lighthouse score on Taskr isn't luck — it came from lazy loading routes, optimizing images, and measuring the impact of each change.

Architecture before code

I separate concerns deliberately. In Taskr: the service layer handles API calls, context manages state, components only render. In the backend: routes call controllers, controllers use services, middleware handles cross-cutting concerns. This isn't about following patterns — it's about writing code that other developers (and future me) can understand without reading every line.

Development and deployment together

My cloud and network training changes how I write code. I think about what happens when the server restarts, when the database connection drops, when a request takes 10 seconds. Taskr's API validates environment variables on startup and exits with a clear error if any are missing — because silent failures in production are worse than loud failures in development.
